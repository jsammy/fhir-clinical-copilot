# fhir-clinical-copilot

A grounded clinical Q&A and pre-visit summary system over HL7 FHIR R4, where every generated
claim cites the FHIR resource it came from.

> **Synthetic data only.** No PHI is used, stored, logged, or sent to any model. The cohort is
> generated by [Synthea](https://github.com/synthetichealth/synthea); no real patient record is
> present in this repository or in any pipeline it describes.

**Status: in progress.** This README documents intended scope alongside what currently works —
sections are marked so the two are never confused.

---

## Why this exists

Clinical summarisation is a plausible-sounding-answer problem. A model that fabricates a
medication or drops an allergy is worse than no model, and "it looked right" is not a release
criterion. This project treats the retrieval, the citation trail, the refusal behaviour and the
evaluation as the product — not as decoration around a prompt.

## Design layers

| Layer | Purpose | Status |
|---|---|---|
| **Data** | Synthea FHIR R4 transaction bundles loaded into a FHIR server (HAPI for dev, AWS HealthLake as the managed option) | Planned |
| **Retrieval** | Bundles flattened into patient-level chunks with resource IDs preserved through to the answer | Planned |
| **Generation** | Cited answers, guardrails, explicit refusals, full audit log of every query | Planned |
| **Agent** | Read-only FHIR exposed as MCP tools; pre-visit summary behind a human approval step | Planned |
| **Evaluation** | Golden Q&A set, groundedness and hallucination scoring, subgroup checks across age and sex | Planned |
| **Documentation** | Model card, ISO-14971-style risk table, PCCP-style change note | Planned |

## Target architecture (AWS)

```
Synthea FHIR R4 bundles
  └─ S3 (raw) → SQS → Lambda (ingest, flatten, chunk)
       └─ Bedrock embeddings → S3 Vectors (or OpenSearch)
            └─ Lambda/API → Bedrock LLM + Guardrails → cited answer
                 ├─ Aurora Serverless — audit log of every query
                 ├─ Secrets Manager — credentials
                 ├─ EventBridge — scheduled evaluation runs
                 └─ OpenTelemetry → Grafana / CloudWatch — latency, cost, eval drift
```

## Safety and scope

- Read-only. The agent is given no FHIR write capability and no tool that can mutate a record.
- Every answer carries resource-level citations; an answer that cannot be grounded is refused
  rather than guessed.
- Not a medical device. Not for clinical use, and not validated for any clinical purpose. This
  is an engineering and evaluation exercise on synthetic data.

## Repository layout

```
src/ingest/      FHIR bundle loading and flattening
src/retrieval/   chunking, embedding, vector search
src/api/         query endpoint, citation assembly, audit logging
src/agent/       MCP tools and the pre-visit summary agent
src/eval/        golden set, groundedness scoring, subgroup analysis
docs/            glossary.md; model card and risk table to follow
notebooks/       exploration
data/            Synthea extracts — gitignored, never committed
```

Loaders are shipped, data is not. Regenerate the cohort with Synthea, or download the published
FHIR R4 sample set, and place it under `data/`.
